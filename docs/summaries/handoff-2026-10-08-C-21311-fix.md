# Handoff — C-21311 In-app editor drops the body's translations

**Date:** 2026-10-08
**Ticket:** C-21311 — any In-app edit deletes the body text's `locales`; title and button keep theirs
**Branch:** `geraldosilva/c-21311-inbox-body-locales` (stacked on `geraldosilva/c-21259-sms-push-bold-blank` at `f55e608f`, PR #226)
**Status:** fixed, verified in Studio on localhost:3000 against the dev API. A frontend PR vendors this build.

## Cause

`getOrCreateInboxElement` builds the canvas body as `{ type, content }`, so the body's `locales` never reach the editor. On save, the inbox branch of `createTitleUpdate` rebuilt the body the same way. The meta copies its `locales` from the stored element and actions keep theirs through `cleanInboxElements`; the body was the only element with no path back.

## What changed

- `createTitleUpdate` (inbox): copies the stored body's `locales` verbatim onto the saved body. The stored body is picked the way the canvas picks it: the first text, or the second when a legacy leading h2 stands in for the title.
- Locales are not routed through Tiptap: the Paragraph round-trip rewrites locale `content` into rich `elements` via the markdown parser.

## Evidence

- vitest 4632 passed; the two new locale tests in `preserveStorageFormat.test.ts` fail without the fix.
- Studio, template `nt_01m4dxct7henbt477zbchg2cv7`: French added in the localization screen for title, body and button. A body edit and a button-label edit each kept all three `fr` entries; the localization screen shows 3/3 translated with body and button marked outdated.
- Before the fix, the same flow on `nt_01m4dw3cyafajttv4aejfsenjw` lost the body's `fr` on a label edit.

## Open / deferred

- The canvas drops body blocks after the first and non-text blocks. Intended: Inbox only renders `title`, `preview` (first text) and `actions` (probe send `1-6ac79ca2-6e485f79a826f1f1823bbd3c`).
- An edited body keeps its old translation, flagged outdated, same as the button.
