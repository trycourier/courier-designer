# Session Handoff: C-21459 — standalone BrandEditor overwrites the brand with defaults

**Date:** 2026-10-14
**Branch:** `geraldosilva/c-21459-data-loss-standalone-brandproviderbrandeditor-shows-defaults`, stacked on `geraldosilva/c-21458-brand-editor-manage-preferences-toggle-writes` (PR #232).

## Root cause

- `BrandEditor` seeded `BrandEditorFormAtom` once, `if (!brandEditorForm)`, on mount. Standalone, the brand is still loading then, so the form got defaults and was never re-seeded. Under `<TemplateEditor brandEditor/>` the data is already loaded, which is why that path worked.
- The footer editor's `Paragraph.onCreate` → `generateNodeIds` dispatch fired `onUpdate` on the empty doc and set `BrandEditorContentAtom` to `""`. `BrandFooter` reads `content ?? markdown`, so `""` beat the loaded markdown and `EditorContent` never loaded it.
- The first edit enabled auto-save, which sent the default form plus the new footer. The backend's `updateSettings` replaces `colors` and any truthy `header`/`footer` wholesale, so everything else was lost.
- GetTenant queried `notification` with an empty id (error), and nothing displayed `templateErrorAtom` on the standalone path.

## Fix

- Seed form and footer content together, once, only when `isTemplateLoading === false` and the loaded tenant matches `tenantId`. A tenant switch also clears the form.
- Until the form is seeded, the canvas header, footer and sidebar show a loader and none of the inputs are mounted, so nothing can be typed or dropped before load. If the load fails they read "Couldn't load the brand." instead.
- The brand is fetched once per tenant. A failed load (e.g. unknown tenant) used to leave `templateData` empty and refetch in a loop, ~6 requests/s.
- Auto-save starts once the form and footer are seeded (an empty footer counts), so a sidebar-only edit on a brand with no footer now saves too.
- `notification` is `@include(if: $includeNotification)`, off without a template id. `BrandProvider` toasts `templateErrorAtom`, like `TemplateProvider`.

## Verification

- `BrandEditor.test.tsx`: seeding waits for the load and uses the loaded values; another tenant's data isn't used; a failed load doesn't refetch. `Editor/Editor.test.tsx`: loaders and no inputs before seeding, the failure message, inputs after seeding. Full `vitest` 4667 passed; build passed.
- Loading state live: with every fetch held 6–8s, header, footer and sidebar show loaders, then the real values. Unknown tenant: one request, "Tenant not found" toast, "Couldn't load the brand." in all three (before: 29 requests in 5s and an endless spinner).
- Live, editor-dev against dev, standalone `<BrandProvider><BrandEditor/>` (local page, not committed):
  - API-created brand (`zz-c21459-api-brand` on `zz-c21459-api-t`): editor shows its values; a footer edit saves only that change; reopening shows everything.
  - Tenant without a brand (`zz-c21459-ui-t`): defaults; header style + footer edits create `bnd_01m4xfrp09ecsrqsm5fkk3kdsh`; reopening shows them.
  - `<TemplateEditor brandEditor/>` on `zz-repro-t`: brand editor shows real values with no save on open; footer edit saves with every other value intact; Back shows it in the template; a reload shows it in both.
- Before the fix the same standalone repro showed `#000000`/no logo/empty footer and saved `colors {#000000,#9CA3AF,#737373}`, empty header, footer `Hi there`.
