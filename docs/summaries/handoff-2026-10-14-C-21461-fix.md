# Session Handoff: C-21461 — opening an SMS or Push template auto-saves an empty body

**Date:** 2026-10-14
**Branch:** `geraldosilva/c-21461-data-loss-sms-push`, on `main`.

## Root cause

- `SMSEditor`/`PushEditor` mount `EditorProvider` with an empty placeholder paragraph while `isTemplateLoading !== false` (the `content` memo returns null until then).
- The Paragraph extension assigns a node id and dispatches on setup, so `onUpdate` fires with that empty doc while `templateEditorContent` is still null.
- `onUpdateHandler` in `SMS.tsx`/`Push.tsx` only bailed on `isTemplateTransitioning`, so it took the new-template branch and queued `setPendingAutoSave` with the empty body, which flushed once loading finished. Email's equivalent path already bails while loading.

## Fix

- Both handlers return early while `isTemplateLoading !== false`, matching `Email.tsx`.

  - Fixed build, same templates re-seeded: only the two load requests, no save, drafts unchanged, Publish disabled. Typing `!` in SMS saved `"Hi there!"`.
