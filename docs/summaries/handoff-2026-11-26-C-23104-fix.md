# Handoff — C-23104 In-app editor opens blank on markdown

**Date:** 2026-11-26
**Ticket:** C-23104 — Design Studio v2: markdown in an In-app heading/body wipes the content on publish
**Branch:** `geraldosilva/c-23104-inbox-markdown-blank` (off `origin/main` at `051a454f`)
**Status:** fixed; frontend PR vendors this build. Live-tested on the frontend's Vercel preview against dev.

## Cause

Deferred item from C-21259. The In-app editor uses `textMarks: "plain-text"` like SMS and Push, but `convertElementalToTiptap` only kept markdown markers literal for `sms`/`push`. `**x**` in an In-app heading or body became a `bold` mark, ProseMirror threw `There is no mark type bold in this schema`, Tiptap fell back to an empty doc, and the next save/publish wrote that empty doc over the content.

## What changed

- `convertElementalToTiptap`: `inbox` joins `sms`/`push` in the literal-marker path.
- `plainTextChannelMarks.test.ts`: In-app case (meta title + text with markers); fails with the fix reverted.
- New `MarkdownPreview` extension, In-app only: decorations that style `**`/`__` bold, `*`/`_` italic and `~~` strike, and hide the markers unless the focused caret touches the span. The parser mirrors courier-web `courier-ui-inbox/src/utils/markdown.ts`, so the editor and Preview & Test match the real Inbox (checked side by side against the courier-web inbox-demo on dev). The doc is untouched, so saving is unchanged.

## Open / deferred

- Inbox block markers (`- ` list items, `> ` quotes) and bare-URL links are not styled in the editor.
- Loaded `[text](url)` links are link marks, so emphasis glued to a link (`[a](u)_b_`) can differ from the Inbox.
- The Inbox skips markdown when the title/body looks like HTML; the editor still styles it.
- A variable chip scans as a non-word char, so `{{id}}_x_` shows italic in the editor while the Inbox (rendered `123_x_`) keeps it literal.

- Content stored as elements-array with `bold: true` flags still emits a mark on all three plain-text channels (unchanged from C-21259).
