# Session Handoff: C-21458 — "Manage Preferences" writes a dead link

**Date:** 2026-10-14
**Branch:** `geraldosilva/c-21458-brand-editor-manage-preferences-toggle-writes`, off `origin/main` at `bc941e75`.

## Root cause

The brand editor's "Manage Preferences" toggle appended `[Manage Notification Preferences]({{urls.preferences}})`, and `convertTiptapToMarkdown` wrote every footer variable chip as `{{id}}`. Brand footers render through the backend's Slate path, which resolves single-brace `{path}` only, so `{{urls.preferences}}` shipped verbatim as the href. The toggle also found its state with `includes("{{urls.preferences}}")`, so a footer with a working `{$.urls.preferences}` link showed it as off, and toggling removed the whole paragraph holding the link.

## Fix

- The toggle writes `{$.urls.preferences}`, the href Studio's v3 brand editor writes (`footer-actions-tiptap.ts`). Detection and removal match `{$.urls.preferences}`, `{urls.preferences}` and the legacy `{{urls.preferences}}`, and removal keeps other text in the link's paragraph (`footerPreferencesLink.ts`).
- `convertTiptapToMarkdown` writes chips as `{id}` and rewrites `{{path}}` inside link hrefs to `{path}`, so any edit to a legacy footer repairs it. Its only callers are the brand footer editor.
- `convertMarkdownToTiptap` reads a single-brace `{path}` as a chip when it is a valid path; anything else stays text.
