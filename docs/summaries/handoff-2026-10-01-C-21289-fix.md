# Handoff — C-21289 inline `img` inside text elements

**Date:** 2026-10-01
**Ticket:** C-21289 (SUP-782, ClearCompany) — CDS drops an `img` placed inside a text element's `elements`
**Branch:** `geraldosilva/c-21289-clearcompany-cds-drops-inline-img-placed-inside-text` (off `origin/main` at `028aea9e`)
**Status:** fixed, verified in Studio against real sends. Frontend PR vendors this build.

## Cause

`convertElementsArrayToTiptapNodes` skipped `img` ("can be added later"), and the editor had no inline image node, so the image vanished on load and was dropped on the next save.

## What changed

- New `InlineImage` tiptap node (`inlineImage`, inline atom; attrs `src`, `alt`, `width`, `href`, `disableTracking`). Registered in `ExtensionKit` and `TranslationEditor` (an unknown node blanks the whole doc).
- Elemental → tiptap emits it; tiptap → elemental writes it back as `{type:"img", src, href?, alt_text?, width?, disable_tracking?}`.
- `typography.css`: inline images keep their own size (`w-auto`, inline-block, `vertical-align: middle`) instead of the blanket `img { width:100% }`.
- Gap decorations: the renderer wraps each inline img in whitespace, so the email shows a space beside it even when the author typed none. A widget decoration shows the same space in the canvas without storing it.

## Evidence

- vitest 4609/4609; `inlineImage.roundtrip.test.ts` (4 tests) fails 3/3 with the converter changes reverted.
- Studio (localhost:3000, dev API): SUP payload, a 10-config matrix (natural, 16/100px, 50%, href, alt, image first / two adjacent, bold+center+link, h1, oversized) and a spacing matrix all match `/messages/{id}/output` HTML side by side, including 1-space gaps (3.7px editor vs 3.9px send). Editor save round-trips every img attr unchanged.

## Open / deferred

- **C-21350** (backend): renderer gives inline img no `max-width`, so an image wider than the column overflows the email. The canvas clamps it (decided with the user).
- No editing UI for inline images (select/delete only). Markdown fallback paths (`splitsBlock`, inbox/sms markdown) do not emit the image.
